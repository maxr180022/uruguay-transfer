2. БРОНИРОВАНИЕ И МАРШРУТЫ
============================================================

«Другие направления» поддерживают до 6 точек:
A → B → C → D → E → F

Для обычной точки:
— город обязателен;
— улица обязательна;
— номер дома необязателен.

Номер дома может отсутствовать в общедоступных картах, поэтому система допускает адрес без номера дома.

Выпадающий список городов отсортирован по алфавиту.

Короткая пометка в «Других направлениях»:
«⚠️ Возможны ошибки, проходит тестирование.»

============================================================
3. ФИКСИРОВАННЫЕ ТРАНСПОРТНЫЕ ТОЧКИ
============================================================

В любой точке A–F можно выбрать готовую транспортную точку без ручного ввода адреса:

— Аэропорт Караско (MVD)
— Аэропорт Пунта-дель-Эсте / Laguna del Sauce (PDP)
— Терминал Buquebus Montevideo

Они являются отдельными узлами внутренней тарифной сети и могут использоваться в любом направлении маршрута.

Контрольные связи внутренней сетки:
— Montevideo ↔ Carrasco Airport: 18 км
— Pando ↔ Carrasco Airport: 28 км
— Punta del Este ↔ Punta del Este Airport: 20 км
— Piriápolis ↔ Punta del Este Airport: 18 км
— Montevideo ↔ Punta del Este Airport: 113 км
— Montevideo ↔ Buquebus: 2 км

============================================================
4. CITY GRID / ТАРИФНЫЙ ДВИЖОК
============================================================

Текущая внутренняя сеть после добавления транспортных точек:
— 78 узлов;
— 129 двусторонних дорожных связей;
— 3003 пары узлов;
— все узлы связаны.

Коммерческий лимит клиентского маршрута:
150 км.

Маршрут свыше 150 км переводится в индивидуальный / Business расчёт.

Основные параметры расчёта:
— базовая часть: 1400 UYU;
— внутренний курс: 40 UYU/USD;
— peaje: 214 UYU;
— эксплуатационная себестоимость: 12.616 UYU/км;
— минимальная защищённая прибыль для обычных рассчитываемых маршрутов: 1500 UYU;
— ожидание в «Других направлениях»: 500 UYU/час.

Обычная зарядка автомобиля уже включена в 12.616 UYU/км и отдельно не добавляется.

============================================================
6. КАЛЕНДАРНЫЙ ДВИЖОК
============================================================

Любой новый заказ можно оформить минимум за 2 часа до подачи.

Межгород:
— расчёт планового времени по внутренней дистанции;
— средняя скорость для календаря: не более 70 км/ч;
— время округляется вверх до ближайших 30 минут.

Это влияет только на календарную занятость, а не на цену.

Обычный трансфер / «Другие направления»:
— время маршрута;
— плюс заявленное ожидание;
— плюс 4 часа резерва после клиентской части.

Личный водитель:
— заказанные часы, минимум 3;
— плюс 4 часа резерва.

Корпоративный заказ:
— 3 часа;
— плюс 2 часа резерва.

Punta del Este туда-обратно:
— 10 часов от выбранного клиентом времени;
— плюс 6 часов резерва;
— время начала может быть любым доступным.

Пересекающиеся бронирования не допускаются.
Pending-заявка уже логически резервирует временной интервал.
Финальная проверка выполняется под ScriptLock.

============================================================
7. ЖИЗНЕННЫЙ ЦИКЛ ПОЕЗДКИ / ОДОМЕТР
============================================================

Водительский сценарий через Telegram:

1. Начать заказ.
2. Ввести начальный одометр.
3. Выехать к точке A.
4. Отметить прибытие в A.
5. Начать поездку с клиентом.
6. Отмечать промежуточные точки и ожидание.
7. Завершить клиентскую часть.
8. Вернуться в Pando.
9. Ввести конечный одометр.
10. Полностью закрыть заказ.

Фактический рабочий пробег:
конечный одометр − начальный одометр.

Фактическая цепочка автомобиля:
Pando → A → B → C → ... → Pando.

============================================================
8. ВНУТРЕННИЕ РАСХОДЫ И ПРИБЫЛЬ
============================================================

Оператор может добавить к заказу внутренний расход:
— парковка;
— дополнительный peaje;
— прочее.

Сумма вводится в UYU.
Клиент эти расходы не видит, и согласованная цена заказа автоматически не меняется.

Фактическая прибыль рассчитывается на основании:
— выручки;
— фактического пробега;
— 12.616 UYU/км;
— peaje;
— парковки;
— дополнительных расходов.

============================================================
9. МЕСЯЧНЫЙ УЧЁТ
============================================================

После полного закрытия заказа данные попадают в постоянный журнал.

Google Sheets:
— «Учёт поездок»;
— «Месячные отчёты».

Месячный отчёт включает:
— количество заказов;
— выручку;
— фактический рабочий пробег;
— себестоимость по километрам;
— peaje;
— парковки;
— прочие расходы;
— общие расходы;
— фактическую прибыль;
— среднюю прибыль на заказ.

В Telegram оператора есть команда/кнопка месячного отчёта.

============================================================
10. TELEGRAM / УВЕДОМЛЕНИЯ
============================================================

Вся серверная Telegram-логика находится в Code.gs.

Клиент получает уведомления по этапам поездки.
Оператор получает карточку заявки, маршрут, календарную информацию и рабочие кнопки управления заказом.

Токены, chat IDs и служебные настройки не хранятся в README и должны находиться в Script Properties.

— клиент;
— маршрут;
— ожидание;
— календарный блок;
— одометр;
— фактический пробег;
— дополнительные расходы;
— фактическую экономику заказа.

Важно:
legacy bridge names UruWayAndroid / UruWayApp и package com.uruway.transfer не переименовываются без отдельной миграции.
